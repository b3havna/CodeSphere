# CodeSphere Deployment Guide

This guide explains how to deploy the refactored **CodeSphere** application with the React frontend hosted on **Vercel**, the Express + Socket.io backend hosted on **Render**, and the database hosted on **MongoDB Atlas**.

---

## 1. Database Setup: MongoDB Atlas

1. **Create an Account / Log In**: Sign up or log in at [MongoDB Atlas](https://www.mongodb.com/cloud/atlas).
2. **Create a Shared Cluster**: Launch a new free tier (M0) cluster in your preferred region.
3. **Database Access (User)**:
   - Navigate to **Security > Database Access**.
   - Create a database user with **Read and Write to any database** privileges.
   - Securely save the password.
4. **Network Access (IP Whitelist)**:
   - Navigate to **Security > Network Access**.
   - Click **Add IP Address**.
   - Since Render servers do not have fixed static IPs on the free tier, you must choose **Allow Access From Anywhere** (`0.0.0.0/0`) to allow Render to connect. Alternatively, if you pay for Render static outbound IPs, add those specific IPs.
5. **Get Connection String**:
   - Go to your Cluster dashboard and click **Connect**.
   - Select **Connect your application (Drivers)**.
   - Choose Node.js driver version.
   - Copy the connection URI:
     `mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0`
   - Replace `<username>` and `<password>` with your database user credentials.

## 2. Backend Deployment: Render

1. **Log In**: Go to [Render](https://render.com) and connect your GitHub/GitLab account.
2. **Create Web Service**:
   - Click **New +** and select **Web Service**.
   - Connect the CodeSphere repository.
3. **Configure Service Details**:
   - **Name**: `codesphere-backend`
   - **Environment**: `Node`
   - **Region**: Select the closest region to your cluster.
   - **Branch**: Select your deployment branch (e.g. `main`).
   - **Root Directory**: `server` (This instructs Render to only build and run from the backend subfolder!)
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
4. **Configure Environment Variables**:
   Click **Advanced** and add the following variables under the **Environment Variables** tab:
   - `PORT`: `5000` (Render will override this, but setting it is good practice)
   - `MONGO_URI`: *Your MongoDB Atlas connection string*
   - `JWT_SECRET`: *A secure random string*
   - `FRONTEND_URLS`: `https://your-project.vercel.app` (Add your frontend URL once generated by Vercel)
   - `JDOODLE_CLIENT_ID`: *Your JDoodle client ID*
   - `JDOODLE_CLIENT_SECRET`: *Your JDoodle client secret*
   - `GROQ_API_KEY`: *Your Groq API key*
   - `GROQ_MODEL`: `llama-3.3-70b-versatile`
5. **Deploy**: Render will build the project and launch the server. Note down your backend URL (e.g. `https://codesphere-backend.onrender.com`).

---

## 3. Frontend Deployment: Vercel

1. **Log In**: Sign in to [Vercel](https://vercel.com) using your GitHub credentials.
2. **Import Project**:
   - Click **Add New > Project**.
   - Connect and import the CodeSphere repository.
3. **Configure Build Settings**:
   - **Project Name**: `codesphere`
   - **Framework Preset**: `Create React App` (Vercel auto-detects this)
   - **Root Directory**: Click Edit, select the `client` folder, and click **Continue**. (This instructs Vercel to build from the frontend subfolder!)
   - **Build Command**: `npm run build`
   - **Output Directory**: `build`
   - **Install Command**: `npm install`
4. **Configure Environment Variables**:
   Under **Environment Variables**, add the single required frontend variable:
   - `REACT_APP_API_URL`: *Your Render backend URL (e.g., `https://codesphere-backend.onrender.com`)*
     - **Important**: Do not add a trailing slash `/` at the end of the URL.
5. **Deploy**: Click **Deploy**. Vercel will build the frontend React application and provide you with a deployment URL (e.g., `https://codesphere.vercel.app`).

---

## 4. Post-Deployment Coordination

Once both apps are built:
1. Go back to your **Render Web Service** settings.
2. Update the environment variable `FRONTEND_URLS` to include your production Vercel URL (e.g., `https://codesphere.vercel.app,http://localhost:3000`).
3. Click **Clear Build Cache and Deploy** to apply the updated CORS configuration on the server.

## 5. Troubleshooting & Socket.io Notes

### WebSocket Upgrade (CORS) Issues
If you see console errors like `Access-Control-Allow-Origin` or WebSocket connection failures in production:
- Ensure that the Vercel domain matches exactly (including `https://` and without trailing slashes) with one of the items inside `FRONTEND_URLS` on Render.
- Verify that `socket.io-client` on the frontend connects using `REACT_APP_API_URL`.

### Render Spin-up Delay
On Render's free tier, the backend web service spins down after 15 minutes of inactivity. When a user visits the frontend after a period of inactivity:
- The backend may take 50-90 seconds to wake up (spin up).
- During this spin-up period, login, signup, and room listings will fail or appear stuck.
- This is normal behavior for Render Free Tier. Consider upgrading to a starter tier for zero cold starts.

---

## 6. How to Redeploy After Future Updates

- **Automatic Deployments**: By default, both Vercel and Render deploy automatically on every push to your main branch.
- **Synchronized Socket Event Constants**: If you add, rename, or change any socket actions, make sure to update both `client/src/actions/Actions.js` and `server/actions/Actions.js` synchronously to prevent real-time sync bugs.
